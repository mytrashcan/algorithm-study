![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%203.png)

```cpp
Set Li = [] for i=1,…,n
L0 = [w], where w is the start node
Mark w as visited
For i = 0, …, n-1:
	For u in L_i:
		For each v which is a neighbor of u:
			If v isn’t yet visited:
				mark v as visited, and put it in L_{i+1}
```

- Runtime: Same as DFS, $O(n+m)$

### Shortest path problem

### Example

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%2010.png)

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%2011.png)

pink vertices = not sure
red node → sure
d[v] = estimate for d(Gates, v)

1. starting vertices가 아닌 노드에는 d[v] = infinite, 
starting vertices는 d[gates] = 0
2. not-sure 노드 u를 선택하고 d[u]를 추정한다.
3. u의 이웃 v를 update 한다.
    1. d[v] = min(d[v], d[u] + edgeWeight(u, v))
4. u를 mark 한다.
5. repeat.

```cpp
Dijkstra(G, s):
	Set all vertices to not-sure
	d[𝑣] = ∞ for all 𝑣 in 𝑉
	d[𝑠] = 0
	While there are not-sure nodes:
		Pick the not-sure node 𝑢 with the smallest estimate d[𝒖]
		For 𝑣 in 𝑢. 𝑛𝑒𝑖𝑔ℎ𝑏𝑜𝑟𝑠:
			d[𝑣] ← min( d[𝑣], d[𝑢] + edgeWeight(𝑢,𝑣))
		Mark 𝑢 as sure
	Now d(𝑠, 𝑣) = d[𝑣]
```

### Useful Properties

1. No-path property
    1. s에서 v로 가는 path가 없으면 d[v] = d(s, v) = infinite
2. Upper-bound property
    1. for all v, d[v] ≥ d(s,v)
    d[v] = min(d[v], d[u] + edgeWeight(u, v))
3. Triangle inequality
    1. s → v가 G에서 shortest path일 때, d[v] = d(s, u) + w(u, v) ≥ d(s, v)이다.
4. Convergence(수렴) property
    1. s → u → v가 G에서 shortest path이고 d[u]가 최단거리로 확정되면, u → v 간선으로 업데이트 시 d[v]도 최단거리로 확정

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%2012.png)

### Why does this work?

- Theorem:
    - G = (V, E), starting from s, Dijkstra.
    - if end, d[v] = d(s, v) for all v.
- Proof:
    - Loop Invariant:
        - while 루프의 각 반복이 시작될 때마다, **sure 리스트에 있는 모든 정점 v에 대해 d[v] = d(s, v)** 이다. (즉, 최단 거리 이다.)
    - Initialization: sure list에 v가 없기 때문에 invariant가 성립한다.
    - maintenance: 귀류법
        - u를 sure list에 넣는다고 가정해보자. 즉, 우리는 smallest d[u]를 가진 u를 선택한다.
        
        ```cpp
        Pick the not-sure node u with the smallest estimate d[u]
        	Update all u's neightbors v:
        			d[v] <- min(d[v], d[u] + w(u,v))
        Mark u as sure
        Repeat
        ```
        
        - 또한 u가 처음으로 d[u] ≠ d(s, u) 인 채로 sure list에 추가되는 노드라 가정하자.
        
        ---
        
        ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%2013.png)
        
        - s는 처음 sure로 추가되는 vertex 이다:
            - 이때 d[s] = d(s, s) = 0 이므로 s ≠ u이다.
        - 경로가 없다면
            - d[u] = d(s, u) = $\infin$ 이므로 가정에 모순이 발생한다.
        - 위 케이스에 의해 s → u 최단 경로 p가 존재함을 알 수 있다.
        
        ---
        
        ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%2014.png)
        
        - x = p에서 마지막 sure vertex
        y = x 다음의 첫 번째 not-sure vertex
        (x = s 일 수도 있고, y = u 일 수도 있음)
        - d[x] = d(s, x) → x는 이미 sure list에 있음 → 귀납 가설(Loop Invariant)에 의해 확정! ✓
        - d[y] = d(s, y) → x가 sure에 추가될 때 x → y 간선으로 update 됨 → Convergence Property에 의해: d[x] = d(s, x) 이었으므로 d[y] = d(s, y) ✓
        
        ---
        
        ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%2015.png)
        
        - d[y] = d(s, y)  (Step 3에서)
        d(s, y) ≤ d(s, u)  (y가 u로 가는 경로 중간에 있으므로)
        d(s, u) ≤ d[u]  (Upper-bound property)
        - 따라서: d[y] = d(s, y) ≤ d(s, u) ≤ d[u]
            - 그런데 u를 선택할 때:
            u는 not-sure 중 d[u]가 가장 작은 노드!
            y도 not-sure! → d[u] ≤ d[y]
        - 합치면: d[u] ≤ d[y] ≤ d[u] → d[u] = d[y] = d(s, y) = d(s, u) → d[u] = d(s, u) → 가정과 모순! 💥
        - 결론: d[u] = d(s, u) 이 항상 성립! → u가 sure list에 추가될 때 항상 최단거리가 확정됨! ✓
        
        ---
        
    - Termination:
        - termination에서 the not-sure list = $\emptyset$ 이므로 sure list = V → 모든 노드 최단거리 확정!
- Runtime:
    
    ① findMin: 가장 작은 d[u] 찾기
    ② removeMin: u를 not-sure에서 제거
    ③ updateKey: u의 이웃 v 업데이트
    
    → n번 반복 (노드 수만큼)
    → updateKey는 m번 (간선 수만큼)
    
    전체:
    O(n × (findMin + removeMin) + m × updateKey)
    
    ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2012.%20Graph%20Algorithms%20III/image%2016.png)
    
    Dense Graph (m ≈ n²):
    O(n²) vs O(n² log n)
    → Array가 유리! ✓
    
    Sparse Graph (m << n²):
    O(n²) vs O((n+m) log n)
    → RB Tree가 유리! ✓

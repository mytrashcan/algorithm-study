## Selection

- 목표: 정렬되지 않은 배열에서 k 번째로 작은 원소를 $O(n)$ 시간 안에 찾아보자.
- SELECT(A, k): A배열에서 k번째로 작은 원소를 return 한다.
- k번째로 작은 원소를 찾는 방법 (naive):
    - 배열을 정렬(MergeSort)한 후 index k 에 위치한 원소를 return 한다.
    - 이때 Worst-case runtime은 $\Theta(nlogn)$이다. (선형 시간 아님)
    
    ```c
    NAIVE_SELECT(A, k):
      A = MERGESORT(A)   ← 정렬
      return A[k]         ← k번째 반환
    
    → Worst Case: Θ(n log n)   (선형 시간이 아님!)
    ```
    

그렇다면 어떻게 Linear-Time Selection을 구현할 수 있을까?

## Linear-Time Selection

### Key Insight

- pivot을 선택하고, partition 하고, 한쪽만 자가호출(재귀) 하자.
    - k = 4, 즉 4번째로 작은 원소를 찾는다고 가정하자.

1. pivot을 random하게 선택한다
2. pivot을 기준으로 partition 한다
    - 왼쪽: pivot보다 작은 값 (unsorted)
    - 오른쪽: pivot보다 큰 값 (unsorted)
3. pivot의 index(i)를 확인한다
    - k == i → pivot이 정답! return
    - k < i → 왼쪽 재귀
    - k > i → 오른쪽 재귀
4. 반복하다 보면 k번째 값을 찾는다

```c
SELECT(A, p, r, k):
  if p == r  →  return A[p]
  q = RANDOMIZED_PARTITION(A, p, r)   ← 랜덤 pivot
  i = q - p + 1
  if k == i   →  return A[q]
  elseif k < i →  SELECT(A, p, q-1, k)
  else         →  SELECT(A, q+1, r, k-i)
```

### Proving Correctness

> 위 코드에서 반복문이 없으므로 Loop Invariant를 사용하기엔 한계가 있다. 그러므로 이번 Correctness 에서는 Induction 기법을 사용한다.
> 
1. Inductive Hypothesis: 크기 n인 배열 A와 정수 k ∈ {1,...,n} 에 대해 SELECT를 실행하면 A의 k번째 작은 원소를 반환한다
2. Base case:
    1. 배열에 원소가 1개뿐이면?
    → p == r 조건에 걸려서 A[p] 바로 반환
    → k=1 밖에 없으므로 1번째 작은 원소 = A[p]
3. Inductive step:
    1. Case 1: $|L| =k-1$인 경우
        1. pivot보다 작은 원소가 정확히 k-1개 따라서 pivot이 바로 k번째 작은 원소임.
        
        ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%206.%20Randomized%20Algorithm%20II/image%203.png)
        
    2. Case 2: $|L| > k-1$인 경우
        1. pivot보다 작은 원소가 k개 이상 있으므로 k번째 원소는 L 안에 있음.
        
        ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%206.%20Randomized%20Algorithm%20II/image%204.png)
        
    3. Case 3: $|L| < k-1$인 경우
        1. pivot보다 작은 원소가 k-1개 미만 따라서 k번째 원소는 R 안에 있음
        
        ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%206.%20Randomized%20Algorithm%20II/image%205.png)
        
4. Conclusion:
    1. Base Case와 Inductive Step이 모두 성립하므로, 귀납법에 의해 모든 n ≥ 1에 대해 성립.
    2. SELECT(A, k)는 k ∈ {1,...,|A|}이면 항상 k번째 작은 원소를 올바르게 반환한다. 

### Analyzing Runtime

- 위 알고리즘은 재귀적인 성격을 가지므로 점화식 T(n)으로 표현할 수 있다.

![len(left), len(right)는 우리가 pivot을 어떻게 선택하냐에 달려있다.](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%206.%20Randomized%20Algorithm%20II/image%206.png)

len(left), len(right)는 우리가 pivot을 어떻게 선택하냐에 달려있다.

- 이상적인 경우, 즉 split을 정확히 반반 할 때:
    - $len(left) = len(left) = (n-1)/2.$
    - $T(n) \le T(n/2) + O(n)$
    - $T(n) \le O(n^d) = O(n)$
- 최악의 경우
    - $len(left) = n-1 , len(right) = 0, vice\space versa$
    - $T(n) \le T(n-1) + O(n)$
    - $T(n) \le O(n^2)$

![위 기법을 사용하더라도 여전히 $\Theta (n^2)$의 시간이 걸린다.](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%206.%20Randomized%20Algorithm%20II/image%207.png)

위 기법을 사용하더라도 여전히 $\Theta (n^2)$의 시간이 걸린다.

## Better method to pick pivot

- 위 에서 개선을 위해 코드를 수정하였으나 여전히 선형 시간에 도달하지 못했다.
- 그렇다면 어떻게 선형 시간에 도달할 수 있을까?
- 이전 예제에서 ideal world를 다시 상기해보자, 이때 partition을 정확히 반반으로 하니 선형 시간이 걸렸다.
    - 이때, 정확히 반반이 아닌, 점근적으로 반반으로 나누게 하는 pivot은 없을까?

### A Good Enough Pivot

- reasonable world에서, 대충 반반으로 나누어보자. such that: $3n/10 < len(left), len(right) <7n/10$.

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%206.%20Randomized%20Algorithm%20II/image%208.png)

- 위 그림에서 만일 큰 partition만 선택하더라도 $T(n) \le T(7n/10) + O(n)$이다. 즉 $T(n) = O(n)$이다.

### Another Divide and Conquer Algorithm

- 우리는 median 값을 선형 시간에 찾는 방법을 모른다. 그러나 충분히 작은 m에서 SELECT(B, m/2)를 사용해 median에 가까운 값 정도는 찾을 수 있다.
- 목표: 충분히 작은 리스트에서 median 값을 찾고 이를 사용해 original 에서 median 값에 가까운 값을 찾자.
    - original list를 small groups로 나눈다.
    - 각각의 small groups에서 sub-median 값을 찾는다.
    - sub-medians의 median값을 찾는다.

- 왜 그런지 알려면, group의 median을 기준으로 element를 partition 해야 한다. 그리고 group을 median-of-median을 기준으로 다시 partition 한다. (그냥 보기좋게 정리하는거임)

![원래 배열을 보기 깔끔하게 정리한 것.](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%206.%20Randomized%20Algorithm%20II/image%2014.png)

원래 배열을 보기 깔끔하게 정리한 것.

- 초록색 선으로 가두어진 원소들은 적어도 median-of-median보다 작다.
    - 이를 공식화 하면 m-o-m보다 작은 원소는 $3\cdot([g/2])-1-1)+2$ 개 존재한다.
        - 이때 첫번째 -1은 m-o-m 자체를, 두번째 -1은 크기가 5가 아닌 list 제외.
- 위 식에 의해 median-of-median보다 큰 원소는 최대 $n-1-(3\cdot[(g/2]-2)+2) \le 7n/10+3$개 존재한다.
    - 이때 $n-1$은 median-of-median 값을 제외한 모든 원소의 개수
- 종합하자면:
    - pivot보다 작은 원소가 최소 $3\cdot([g/2]-2)+2\ge3n/10-4$개 존재한다.
    - pivot보다 큰 원소가 최대 $7n/10+3$개 존재한다.

$$
3n/10 - 4 \le len(left) \le 7n/10 +3 \\ 3n/10-4 \le len(right) \le 7n/10+3
$$

- 따라서 재귀 호출의 최대 크기는 $7n/10$이므로 선형 시간 내 Selection이 가능하다.

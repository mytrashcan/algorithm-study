## Sorting

- 우리는 지금까지 comparisons에 기반한 sorting algorithm들을 보았고, 이 알고리즘들은 $\Theta(n^2)$, $\Theta(nlogn)$시간이 걸린다는 것을 알았다.

### Comparison-Based Sorting

- Theorem: comparison-base sorting은 최소 $\Omega(nlogn)$시간이 걸린다.
- decision tree를 사용해 위 Theorem을 검증해보자.

### Decision Tree

- Decision Tree는 어떠한 comparison sort의 추상화 이다.

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%207.%20Linear-Time%20Sorting/645cde81-b454-4016-a0e0-166c95384585.png)

- leaf는 item의 모든 가능한 순서이다.
- 특정 입력에 대한 런타임 = 그 입력이 따라가는 경로의 길이 = Ω(경로의 길이)
    - Worst Case 런타임 = 가장 긴 경로의 길이 = 트리의 깊이(depth)

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%207.%20Linear-Time%20Sorting/image.png)

- n개 원소의 모든 가능한 순열 수 = n! → Decision Tree의 리프는 최소 n!개
- n!개의 리프를 가진 이진 트리 중 가장 얕은 것은 완전 이진 트리
    - 완전 이진 트리의 깊이 = lg(n!)
        - n! ≈ (n/e)^n  (Stirling's formula)
        - lg(n!) ≈ n·lg(n/e) = Ω(n log n)
- 모든 Decision Tree의 최장 경로 ≥ Ω(n log n)

### Conclusion

1. 모든 비교 기반 정렬은 Decision Tree로 표현 가능
2. Worst Case 런타임 = Decision Tree의 깊이
3. n!개의 리프를 가진 모든 트리의 깊이 ≥ Ω(n log n)
4. 따라서 모든 비교 기반 정렬의 Worst Case ≥ Ω(n log n)

## Can We Do Better?

- 우리는 위 증명을 통해 비교 기반의 정렬 알고리즘은 절대 $\Theta(nlogn)$보다 빠를 수 없음을 증명하였다.
- 그렇다면, 선형 시간 정렬은 정말 불가능할까?
    - 사실은 어떤 assumptions를 사용하면 가능하다.
    - 이제, Counting Sort, Radix Sort, Bucket Sort에 대해 알아보자.

## Counting Sort

- Assumption: 각각의 input은 0 ~ k 범위 안의 값이다.
- Intuition: k보다 작은 원소의 수를 세고, k의 position을 찾는다.

네번째 for문 수행 후

1. C 배열을 0으로 초기화 한다.
2. A 배열을 한 번 순회하면서 각 값이 나올 때마다 해당 값을 index 로 하는 C의 값을 1 증가시킨다.
3. C 배열의 각 값을 누적합으로 변환시킨다.
4.  B 배열에 A 배열의 (index)마지막값 부터 C 배열에 해당하는 위치를 보고 해당 입력한 다음 해당 값을 index 로 했던 C의 값을 하나씩 줄인다.

> Counting sort는 stable한 sort이다. 
Stable은 기존 배열의 정렬 상태가 유지된 상태로 정렬이 됨을 의미한다.
> 

### Counting Sort - Runtime Complexity

Counting Sort의 Worst-case runtime은 $\Theta(n+k) = \Theta(n) \space for \space k = O(n)$이다.

## Radix Sort

- Assumption: Radix sort는 수의 각 자릿수에 대하여 정렬한다.
- Intuition: 각각의 자릿수에 대해서 stable한 sort algorithm을 수행한다.

### Radix Sort - Runtime Complexity

- 각각의 digit이 0 ~ k-1까지의 범위이고 stable sort로 counting sort를 사용한다 가정하자.
- 이때, Radix Sort의 runtime은 $T(n) = \Theta(d(n+k))$, 이때 $d$는 상수이고, $k = O(n)$이다. 그러므로 $O(n)$시간에 작동한다.
    - 이때 $d$는 기수의 크기이다.

## Bucket Sort

- Assumption: 입력 데이터는 무작위로 생성되며, 값들이 [0, 1) 구간에 균등하게 분포되어 있다고 가정한다.
- Intuition:
    1. [0, 1) 구간을 n개의 동일한 크기의 구간(버킷)으로 나눈다
    2. 입력된 n개의 값을 각 버킷에 분배한다.
    3. 각 버킷 안에서 정렬한다.

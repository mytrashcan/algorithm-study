점근적 표기법은 알고리즘의 **시간 복잡도(Time Complexity)** 또는 **공간 복잡도(Space Complexity)** 를 입력 크기 `n`이 충분히 커질 때를 기준으로 나타내는 방법

## Big-O Notation

### 정의

함수 `f(n)`이 `O(g(n))`이다 ⟺ 충분히 큰 모든 `n`에 대해 다음을 만족하는 양의 상수 `c`, `n₀`가 존재한다:

`0 ≤ f(n) ≤ c · g(n),  for all n ≥ n₀`

### 의미

- `f(n)`은 결국 `g(n)`보다 **빠르게 증가하지 않는다**
- 알고리즘의 **최악(Worst Case)** 성능을 나타낼 때 주로 사용
- "이 알고리즘은 아무리 나빠도 이 속도보다 느리지 않다"

### 예시

| f(n) | O 표기 | 이유 |
| --- | --- | --- |
| 3n + 5 | O(n) | c=4, n₀=5 설정 가능 |
| n² + n | O(n²) | 최고차항만 남김 |
| log n + 1 | O(log n) | 상수 무시 |

## Big-Omega Notation

### 정의

함수 `f(n)`이 `Ω(g(n))`이다 ⟺ 충분히 큰 모든 `n`에 대해 다음을 만족하는 양의 상수 `c`, `n₀`가 존재한다:

`0 ≤ c · g(n) ≤ f(n),  for all n ≥ n₀`

### 의미

- `f(n)`은 결국 `g(n)`보다 **느리게 증가하지 않는다**
- 알고리즘의 **최선(Best Case)** 성능을 나타낼 때 주로 사용
- "이 알고리즘은 아무리 좋아도 이 속도보다 빠르지 않다"

### 예시

| f(n) | Ω 표기 | 이유 |
| --- | --- | --- |
| 3n + 5 | Ω(n) | c=1, n₀=1 설정 가능 |
| n² + n | Ω(n²) | 하한도 n² |
| n log n | Ω(n) | n log n ≥ n |

## Big-Theta Notation

### 정의

함수 `f(n)`이 `Θ(g(n))`이다 ⟺ 충분히 큰 모든 `n`에 대해 다음을 만족하는 양의 상수 `c₁`, `c₂`, `n₀`가 존재한다:

`0 ≤ c₁ · g(n) ≤ f(n) ≤ c₂ · g(n),  for all n ≥ n₀`

### 의미

- `f(n)`과 `g(n)`은 **같은 증가율**을 가진다
- **O와 Ω를 동시에 만족**할 때 성립: `Θ(g(n)) = O(g(n)) ∩ Ω(g(n))`
- 알고리즘의 **평균적인 정확한 성능**을 표현

### 예시

| f(n) | Θ 표기 | 이유 |
| --- | --- | --- |
| 3n + 5 | Θ(n) | 상한·하한 모두 n |
| n² + n | Θ(n²) | 지배항은 n² |
| 2 log n | Θ(log n) | 계수 무시 |

### 세 표기법 비교/요약

| 표기법 | 의미 | 경계 | 비유 |
| --- | --- | --- | --- |
| O(g(n)) | 상한 (Upper Bound) | f ≤ c·g | "최대 이만큼" |
| Ω(g(n)) | 하한 (Lower Bound) | c·g ≤ f | "최소 이만큼" |
| Θ(g(n)) | 정확한 한계 (Tight Bound) | c₁·g ≤ f ≤ c₂·g | "딱 이만큼" |

### 증명 방법

적절한 c와 n₀를 찾는 것이 핵심

1. f(n)과 g(n) 확인
2. 부등식 세우기 → f(n) ≤ c * g(n) 형태로 변환
3. c와 n₀값 제시
4. 검증

O  →  Over  (이것보다 위로 안 감)   →  올림으로 c 잡기
Ω  →  Under (이것보다 아래로 안 감) →  내림으로 c 잡기
Θ  →  둘 다  (딱 이 구간 안에 있음) →  O, Ω 동시 만족

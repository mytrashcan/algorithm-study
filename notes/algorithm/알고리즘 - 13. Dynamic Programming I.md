## Bellman-Ford Algorithm

- Dijkstra’s Algorithm보다 느리다.
- negative edge weights를 다룰 수 있다.
    - Negative Cycle이 존재할 시 Dijkstra에서는 Shortest path가 정의될 수 없다.
- Weights change에 유연하게 대응할 수 있다.
- Dijkstra:    특별한 u를 골라서 u의 이웃만 업데이트
Bellman-Ford: 그냥 모든 노드를 업데이트

### Interpretation of $d^{(i)}$

- $d^{(i)}[v]$는 $s$와 $v$사이의 $i$개의 edges를 가지는 shortest path이다.

- $d^{(0)}$는 0개의 edge 
$d^{(1)}$는 1개의 edge
…
$d^{(4)}$는 4개의 edge
- i가 edge의 사용 개수임.

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2013.%20Dynamic%20Programming%20I/image%202.png)

### Why does Bellman-Ford work?

- I.H.
    - $d^{(i)}$는 $s$와 $v$사이의 $i$개의 edges를 가지는 shortest path의 cost와 동일하다.
- Conclusion
    - $d^{(n-1)}$는 $s$와 $v$사이의 $n-1$개의 edges를 가지는 shortest path의 cost와 동일하다.
    - $n-1$개의 edges로 구성된 shortest path는 shortest simple path라 불리우고 이는 shortest path와 동일하다.
- Aside
    - $n$개 이상의 edges를 사용하는 path에는 반드시 하나 이상의 사이클이 존재한다.
    - shortest path의 정의에 의해 negative cycle은 존재할 수 없다. 이에 의하면 이 사이클은 negative가 아니다.
    - path로 부터 모든 cycle을(positive or zero) 제거했을 때, path는 $n-1$ 개 혹은 더 적은 수의 edges로 구성되어 있고 거기에 반드시 shortest path가 존재한다.

### Proof by induction

- I.H.
    - $i$번 반복 후, 각각의 $v$에 대해서 $d^{(i)}[v]$는 $s$와 $v$사이에 $i$개의 edges로 구성된 shortest path의 cost와 동일하다.
- Base case
    - 0번 반복 후, $d^{(0)}[v]$
    
    ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2013.%20Dynamic%20Programming%20I/image%203.png)
    
- I.S.
    - I.H.가 $i$를 hold한다고 가정하자.
    
    ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2013.%20Dynamic%20Programming%20I/image%204.png)
    
    - 그렇다면, $d^{(i+1)}[v]$는 $min\{d^{(i)}[v], d^{(i)}[u]+w(u,v)\}$에 의해 결정된다. (이때, $d^{(i)}[u]$는 $i$개의 edges를 가지는 shortest path이다.)
    - 그러므로 $d^{(i+1)}[v]$는 $i+1$번째 반복에서 $i+1$개의 edges를 가지는 shortest path이다.
- Conclusion
    - $d^{(n-1)}$는 $s$와 $v$사이의 $n-1$개의 edges를 가지는 shortest path의 cost와 동일하다.
    - 그리고 만약 negative cycles가 존재하지 않으면 $d^{(n-1)}[v]$는 shortest path의 costs와 동일하다.

### Negative cycles in B-F

- 이 그림에서 Gates to the Office의 shortest path는 무엇인가?
- B-F는 negative edge weights에서 잘 작동한다. 단 negative cycles이 존재하면 말이 달라진다.
- 그러나 B-F는 negative cycles를 detect할 수 있다.
- Correctness에 돌아가서 Conlcusion을 보면, negative cycles가 존재할 시 non-simple path matter!

![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2013.%20Dynamic%20Programming%20I/image%205.png)

### How B-F deals with negative cycles

- 만약 negative cycles가 없다면
    - 잘 작동함
    - n - 1 번 라운드 후 값이 안정화 → 정상 종료
- 만약 negative cycles가 있다면
    - 어떤 경우에서 작동하지 않음
    - d[v]의 값이 계속해서 바뀔것 임. → 음수 사이클 감지
- 이를 해결하기 위해 n번째 라운드를 한 번 더 실행!
    - n-1과 n번째가 다르다면 negative cycle return!

## Dynamic Programming

- 피보나치 수는 어떻게 계산하는가?
    - F(n) = F(n-1) + F(n-2), F(1) = F(2) = 1 임을 우리는 알고 있다.
- Question

### What is dynamic programming

- Divide and Conquer처럼 알고리즘을 설계하는 방법론!
- 차이점:
    - D&C: 부분 문제들이 독립적
    DP:  부분 문제들이 겹침(Overlapping)

### Elements of dynamic programming

1. Optimal Substructure
    1. 큰 문제들을 작은 서브 문제들로 break up
    2. 큰 문제를 작은 문제들의 정답으로 추출
2. Overlapping Subproblems
    1. 같은 부분 문제가 반복해서 등장
    2. 이는 sub-problem을 한번 푼 뒤 그 정답을 저장하면 시간을 아낄수 있음.
    
    ![image.png](%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98%20-%2013.%20Dynamic%20Programming%20I/image%2010.png)
    

즉, 

① 작은 문제의 해를 테이블에 저장!
② 저장된 해를 이용해 큰 문제 해결!
③ 최종적으로 전체 문제의 해를 구함!

### Approach of DP

1. Top-down: 큰 문제부터 재귀로 내려가되 이미 계산한 것은 저장해서 재사용!
    
    ```cpp
    F = [0, 1, None, None, ..., None]
    
    def Fibonacci(n):
      if F[n] != None:    ← 이미 계산한 것은 바로 반환!
        return F[n]
      else:
        F[n] = Fibonacci(n-1) + Fibonacci(n-2)
      return F[n]
    ```
    
2. Bottom-up: 작은 문제부터 차례대로 해결
    
    ```cpp
    F[0] = 0  ← 가장 작은 문제부터!
    F[1] = 1
    F[2] = F[1] + F[0] = 1
    F[3] = F[2] + F[1] = 2
    ...
    F[n] = F[n-1] + F[n-2]  ← 최종 답!
    ```
    
    ```cpp
    d^(0)[v] 계산  ← 간선 0개
    d^(1)[v] 계산  ← 간선 1개
    ...
    d^(n-1)[v] 계산  ← 최종 답!
    ```
    
3. Memo-ization: 이미 계산한 부분 문제의 답을 테이블(F)에 저장해두고 재사용
    1. 같은 문제를 두 번 계산하지 않음

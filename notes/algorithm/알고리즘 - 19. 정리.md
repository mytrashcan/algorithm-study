6. Dijkstra
    1. 동작: 
        1. starting vertex의 d = 0, 나머지 vertex들의 v = inf로 설정
        2. not-sure 노드 u를 선택하고 d[u]를 추정
        3. u의 이웃 v를 update
            1. 이때 d[v] = min(d[v], d[u] + w(u, v)
        4. u를 mark
        5. repeat
    2. Claim: Shortest Path의 sub-path는 Shortest path이다.
    3. Properties:
        1. No-path property: no path for s → v then d[v] = d(s, v) = infinite
        2. Upper-bound property: for all v, d[v] ≥ d(s, v), d[v] = min(d[v], d[u] + w(u, v))
        3. Triangle inequality: In G, If s → v is shortest path then d[v] = d(s, u) + w(u, v) ≥ d(s, v)
        4. Convergence property: In G, If s → u → v is shortest path and d[u] is sure then updating u → v assure that d[v] is shortest path.
    4. Why does this work?: 
        1. Invariant: 각 루프때마다 sure 리스트에 있는 모든 정점 v에 대해 d[v] = d(s,v) 이다.
        2. 귀류법: 
            1. d[u] ≠ d(s,u)인 u를 sure list에 넣는다고 가정하자.
            2. d[s] = d(s, s) = 0 이므로 s ≠ u 이다.
            3. x는 p에서 마지막 sure vertex, y는 x 바로 다음 not-sure vertex이다.
            4. d[x] = d(s, x)이고, d[y] = d(s, y)이다. (Convergence Property)
            5. 이때, d[y] = d(s, y) ≤ d(s, u) ≤ d[u] 이다. (y가 u까지 가는 최단경로 p 위에 있기 때문)
            6. 그러나 y, u 모두 not-sure list 이기때문에, 만약 u를 선택한다면 d[u] ≤ d[y]에 따라서 d[u] = d(s, u)이므로 모순이 발생한다.
    5. Time: 
        1. Array: $O(n^2)$ (dense 유리)
        2. RB Tree: $O((n+m)logn)$ (sparse 유리)

## DP

1. When/How to DP?
    1. **Overlapping Subproblems**
    2. **Optimal Substructure**
    3. Recursive Formulation
    4. Dynamic Programming
2. Bellman-Ford
    1. recursive-formulation:
     $d^{(i+1)}[v] \leftarrow min(d^{(i)}[v], min_{\text{u in v.inNbrs}}(d^{(i)}[u]+w(u,v))$
    2. Time: $O(mn)$
3. Floyd-Warshall
    1. recursive-formulation:
    $D^{(k)}[u,v] = min(D^{(k-1)}[u, v], D^{(k-1)}[u,k]+D^{(k-1)}[k,v])$
    2. Time: $O(n^3)$
4. LCS
    1. recursive-formulation: 
    $C[i,j] = 1 + C[i-1, j-1], \\C[i,j] = max(C[i-1,j],C[i,j-1])$
    2. Time: $O(mn)$
    3. LCS length: 
    
    ```java
    for i = 1 to m
      for j = 1 to n
        if X[i] == Y[j]:
          curr[j] = prev[j-1] + 1 # 이전 대각선 값 참조
        else
          curr[j] = max(curr[j-1], prev[j])
      prev = curr
    ```
    
    iiii. Backtracking: 
    
    ```java
    while i > 0 and j > 0
      if X[i] == Y[j]
        add X[i] in array
        --i; --j;
      elif C[i-1][j] > C[i][j-1]
    	  --i;
    	else
    		--j;
    ```
    
5. Knapsack Problem
    1. recursive-formulation: 
    $K[x,j] = max(K[x,j-1], K[x-w_j, j-1] + v_j), \\ K[x,0] = K[0,j] =0$
    2. Time: $O(nW)$

## Greedy

1. Activity Selection
    1. 일련의 선택을 하기.
        1. 가장 빨리 끝나는 activity 선택
    2. 매 선택이 optimal solution을 배제하지 않음을 보임
        1. Greedy 선택 k가 T*에 없더라도, T*의 다른 activity와 k를 **swap** 하더라도 T* 보다 나빠지지 않음 → optimal solution 여전히 존재
    3. 모든 선택이 끝난 이후에도 optimal solution을 배제하지 않음!
2. Huffman Coding
    1. Computation: $Cost(tree) = \Sigma_{leaves x}P(x) \cdot depth(x)$
    2. Lemma-1: x, y are least-frequent letters, and there is a optimal tree that x and y is siblings.
    3. Lemma-2: C is alphabet set, x and y have minimum frequency in C, C` is z that x and y are eliminated. (z = x + y). 
    In this case, T` is optimal for C`.
    Then, In T`, eliminate z then add x and y, lead to new tree T is optimal.
        1. Cost(T) = Cost(T`) + x.freq + y.freq
        2. Proof(Con’d)
            1. T is not optimal
            2. Cost(T``) < Cost(T) is exist (T`` have x and y as a sibling)
            3. Cost(T``) = Cost(T`` - {x, y}) + x.freq + y.freq
            4. Cost(T`` - {x, y}) = Cost(T``) - x.freq - y.freq
            5. Cost(T`` - {x, y}) < Cost(T) - x.freq - y.freq
            6. Cost(T`` - {x, y}) < Cost(T`)

## NP

1. P: 다항 시간 내 해결 가능
2. NP: 답이 주어지면 다항 시간에 검증 가능
3. NP-Hard: 모든 NP 문제보다 어렵거나 같은 수준
4. NP-Complete: NP에 속하면서 NP-Hard인 문제
5. Relations:
    1. $P \subseteq NP \\
    NP-Complete \subseteq NP \\
    NP-Complete \subseteq NP-Hard \\
    NP-Complete = NP \cap NP-Hard$
